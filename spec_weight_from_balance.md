# Спека: «Тяжесть от остатка»

> Бриф для код-сессии. Фича №1 из [backlog.md](backlog.md). Стек по концепту: Vite + TS без фреймворка,
> drag на Pointer Events, состояние в localStorage. Реализация — в отдельной сессии.

## Что делаем (суть)

При перетаскивании мешка в сундук «Траты» мешок **сопротивляется пальцу тем сильнее, чем большую долю
текущего остатка ты сейчас отдаёшь**. Отдать 5к при остатке 8к — тяжело, мешок вязко тянется.
Те же 5к при остатке 80к — почти невесомо, летит за пальцем.

Цель: вернуть трение на КАЖДУЮ значимую трату, а не только в редкий день с мешком 50к.
Тяжесть — отдельный сенсорный канал (усилие в пальце), не дублирует «пустеющую комнату» (это глаз).

## Логика

**1. Доля траты (cost fraction).** В момент, когда мешок «взят» на перетаскивание:

```
fraction = bagValue / remaining
```

- `bagValue` — номинал перетаскиваемого мешка.
- `remaining` — **сколько осталось отдать** = баланс комнаты − то, что уже лежит в сундуке «Траты» в этой сессии.
  (Т.е. каждый следующий мешок в одной трате тяжелее предыдущего — чем больше уже накидал, тем тяжелее добавить ещё. Это по духу.)
- `fraction` зажимается в `[0, 1]`.

**2. Сопротивление (resistance).** Небольшие доли почти не мешают, крупные — драматично тяжёлые (нелинейно):

```
resistance = base + (1 - base) * pow(fraction, k)
```

Стартовые значения (тюнятся по ощущению):
- `base = 0.05` — даже копеечная трата имеет чуть-чуть веса, не «мыло».
- `k = 1.5` — кривая: мелочь еле цепляет, крупная доля резко тяжелеет.

`resistance ∈ [0.05 … 1]`.

**3. Что делает resistance физически — вязкое отставание мешка от пальца.** Мешок не приклеен к курсору,
а догоняет его с инерцией; чем тяжелее, тем сильнее отстаёт и тем медленнее ползёт:

```
follow = lerp(fastFollow, slowFollow, resistance)   // доля пути к пальцу за кадр
bagPos += (pointerPos - bagPos) * follow * (dt / 16.7)   // dt-нормировка, чтобы не зависеть от FPS
```

Стартовые значения:
- `fastFollow = 0.9` — лёгкий мешок практически прилипает к пальцу.
- `slowFollow = 0.12` — тяжёлый ползёт вязко, заметно отставая.

Реализация цикла — `requestAnimationFrame`, `dt` в мс между кадрами.

## Крайние случаи

- **Отдаёшь всё или больше остатка** (`fraction ≥ 1`): `resistance = 1`, максимально тяжело. НЕ блокируем — трение, а не запрет (принцип концепта «хочет обманывать — пусть»).
- **Копейки при большом остатке** (`fraction → 0`): `resistance → base`, мешок снапится к пальцу. Не должно раздражать.
- **`remaining ≤ 0`** (баланс уже 0, или всё застолблено в сундуке): считаем `fraction = 1` → максимальная тяжесть.
- **Кошелёк мелочи (<1000 ₽)**: он число в углу, НЕ мешок — под эту механику не попадает вовсе.
- **Возврат мешка из сундука в комнату**: обратное перетаскивание — БЕЗ сопротивления (лёгкое). Тяжесть только на «отдаче».

## Что НЕ делаем в этой фиче

- Не блокируем и не отменяем трату из-за тяжести.
- Не трогаем денежную логику (раскладку по номиналам, размен, баланс) — только поведение drag.
- Не рисуем повреждения/износ мешка (это отдельная фича «початый мешок», паркинг).
- Без звука/вибро (отдельная фича №5).
- Без «удержания на отпускании» (отдельная фича №7). Здесь — только сопротивление во время движения.

## Как валидирую (тест ощущением)

Живу с MVP неделю-полторы и проверяю:
1. Крупная по доле трата реально заставляет притормозить рукой? (должна)
2. Мелкая трата остаётся лёгкой и не бесит? (должна)
3. Вязкость приятная или раздражающая? → крутим `slowFollow` (больше = легче) и `k` (больше = резче делит мелочь/крупняк).
4. Вердикт: **оставляем / крутим числа / убираем.**

## Открытые решения (нужен твой выбор перед кодом или по ходу)

- `remaining` считать от **живого остатка минус уже застолблённое в сундуке** (рекомендую, «следующий мешок тяжелее») —
  или фиксировать долю от баланса на момент старта траты (проще, но каждый мешок независим). **По умолчанию: первый вариант.**
- Стартовые константы (`base`, `k`, `fastFollow`, `slowFollow`) — это отправная точка, финал подберём по ощущению.
